# Polished Crystal v3.3.0 save migration

## Scope and reproducibility

- Source: [`v3.2.3`, `3fa43192379df5c3e7b09a08e4d5d79af4f02f42`](https://github.com/Rangi42/polishedcrystal/tree/3fa43192379df5c3e7b09a08e4d5d79af4f02f42), save version 10.
- Destination: [`master`, `84acd5a45e32b368755254cee44e6df8344ddfaf`](https://github.com/Rangi42/polishedcrystal/tree/84acd5a45e32b368755254cee44e6df8344ddfaf), save version 11. The final upstream commit bumps `SAVE_VERSION` from 10 to 11; its parent is `8b2bbb076731cec99c399809015043d6a2f2a51c`.
- This release was initially described as v3.2.4 and renamed to v3.3.0 during preparation. The upstream Makefile still labels the audited build `3.2.3`; the save format is 11.
- Both revisions were built in Ubuntu WSL with RGBDS 1.0.4. `resources/version11/version11.sym` is the destination build's symbol output. Save-layout symbols were compared with the source build and the existing version 10 resource.
- Regenerate the map table with `python3 tools/generate_v11_maps.py /path/to/polishedcrystal`. The script reads the pinned commits with `git show`, checks every removed map against an explicit rename/split/merge decision, and derives return warps from the destination map scripts.
- Verify option encodings, facility set/trainer tables, and labeled-PR ancestry with `python3 tools/audit_v11_tables.py /path/to/polishedcrystal`. Append the old and new `.gbc` paths (with adjacent `.sym` files) to compare all 432 existing facility sets in the assembled ROMs.

Only released version 10 saves are supported as direct input. Intermediate master builds used version 10 while these incompatible changes accumulated. They cannot be reliably distinguished using the save-version field. The v3.2.0–v3.2.3 map IDs, event IDs, and Pokemon form definitions agree; the intervening map-constant change is a Dance Theatre height change, irrelevant to the required upstairs save location.

## Layout findings

There are no SRAM relocations, changes to saved-block sizes, or changes to the offsets of surviving fields inside player, map, and Pokemon data. Three WRAM labels change names in place: `wUndergroundSwitchPositions` becomes `wFollowInSync`, and the Faraway Island and Goldenrod underground scene variables are renamed.

| Saved data | File offsets (end exclusive) |
| --- | --- |
| Main game data | `0x2008..0x2b83` |
| Backup game data | `0x1208..0x1d83` |
| Main / backup checksums | `0x2d0d` / `0x1f0d` |
| Save version, big endian | `0x0be2` |

The migration verifies both source checksums and requires the player to be upstairs in a Pokemon Center (`20:1`). It rejects an interrupted backup write, invalid party counts, repeat conversions, and downgrades. The output starts as a complete copy of the input, preserving the emulator/RTC trailer. After conversion it rebuilds the backup game-data block from the main block, as earlier patch versions do, then recalculates both checksums and writes version 11.

## Labeled PR cross-check

Queried all merged PRs with `version/minor`, then checked each merge commit's ancestry against **both pinned revisions**. A date filter is insufficient: v3.2.3 is on the release history, and #1301 was merged before the tag's date but is absent from that tag. Five merged PRs currently have this label; three are in the migration range. #993 and #1137 are already ancestors of v3.2.3.

The initial implementation missed the #1301 roamer initialization and #1566 rental-party IDs, and cleared opponent history instead of translating it. The follow-up PR-label review corrected these gaps and added explicit option tests; the new text-pause flag is also now initialized. This document describes the corrected implementation.

The facility source tables contain 61/140/143/88 old sets and 61/140/144/89 new sets (D/C/B/A). All 134 trainer table positions are stable, despite changes to ROM name padding and class constants, so their saved indexes must be preserved. The SRAM rental-party field aliases normal Tower party selections; conversion is gated by `BATTLETOWER_RENTALMODE` to avoid treating those selection bytes as set IDs.

## Initial and in-game options

Reviewed [#1316](https://github.com/Rangi42/polishedcrystal/pull/1316), [#1359](https://github.com/Rangi42/polishedcrystal/pull/1359), [#1390](https://github.com/Rangi42/polishedcrystal/pull/1390), the intervening option-order commit, endpoint constants, menu handlers, defaults, save/load routines, and both saved option blocks. Scrolling, descriptions, and menu ordering do not change existing settings' encodings. The defaults label moved to include `wOptions3`; the SRAM layout did not move.

| Saved field | Encoding and migration |
| --- | --- |
| `wOptions1` | Preserve text speed (bits 0–1), autoscroll (2–3), turning speed (4), text-scroll state (5), sound (6), and battle effects (7). The old WRAM comment about speed order is stale; constants and both menu implementations agree on Slow/Medium/Fast/Instant = 0/1/2/3. |
| `wOptions2` | Preserve typeface (0–2), running shoes (3), clock format (4), dex units (5), and battle style (6–7). |
| `wOptions3` | Preserve QWERTY (0) and unrelated bits. Clear newly allocated nickname Always/Never bits (1–2), selecting **Ask** in both `sOptions3` and `sBackupOptions3`. |
| `wTextboxFrame`, `wSaveFileExists` | Preserve unchanged. |
| `wTextboxFlags` | Clear newly allocated `NO_TEXT_PAUSE_F` (5) in both copies; retain existing bits. This is temporary description-rendering state, not a user preference. The menu sets and restores it, so inheriting a stale set bit could suppress later dialogue pauses. |
| `wInitialOptions` | Preserve natures, abilities, color variation, perfect IVs, traded behavior, affection, scaled EXP, and physical/special split (bits 0–7). |
| `wInitialOptions2` | Preserve EV mode (0–1), no EXP (2), RTC (3), evolution in battle (4), unused bits, and `RESET_INIT_OPTS` (7). No new initial option or encoding requires a reset. |

Version 9→10 already sets `RESET_INIT_OPTS`. Chaining from an older save keeps that pending prompt; a normal version 10 save with the bit clear remains clear. The version 11 step does not reset initial choices. Primary and backup options are converted independently because they lie outside the game-data/checksum blocks.

## Incompatible values and conversions

| Change | Migration |
| --- | --- |
| Orange Arbok inserted as form 3 | Old Arbok forms 3–5 become 4–6. Species must be Arbok **without** the extended-species bit; gender/egg bits are preserved. Other species' stored species/form bytes do not shift. |
| Legendary encounter code now reads saved roamer forms | Initialize Raikou, Entei, and Suicune to `PLAIN_FORM`; the old form byte was uninitialized. |
| Flattened dex index `0x140` inserted | Shift seen and caught bits from old species index `0x140` onward by one, leave Orange Arbok unseen/uncaught, and clear unused padding. Each dex array still occupies 50 bytes. |
| Pokemon League spawn inserted at index 15 | Shift visited-spawn bits 15–33 up one. Enable the new League destination if Indigo Plateau was already visited. The array remains five bytes. |
| Map reordering, renames, splits, merges | Translate persistent map pairs for respawn, Yanma/Dunsparce swarms, roamers, and the Pokemon Center return. The current map remains the shared upstairs. The generated table includes only changed pairs and applies each translation once. |
| Warp indexes and map geometry changed | Derive the upstairs return warp and outdoor Dig return from the current center's destination map script. Snowtop no longer has stairs: return to its first-floor entrance. Unrecognized upstairs return maps, including legacy patch fallbacks to the player's house, go to Goldenrod with the Plain Badge or Cherrygrove without it. |
| Underground switch puzzle redesigned | Clear old switch flags 606–620; retain the old emergency-switch state as the new emergency-door state (bit 620). Other door positions reset for the redesigned puzzle. Clear the repurposed follower-sync byte. |
| New events allocated at 2259–2286 | Clear the newly allocated range, then initialize the hidden Beta avatar and Firebreather ashes flags. Hide Beta's Cinnabar double for legacy avatars. Preserve unrelated progression flags. |
| Firebreather Dick renamed Cyd; a new Dick added | Keep the old beaten flag at 1070, now Cyd. The new Dick's flag 2268 starts clear. Name-based matching would incorrectly move old progress. |
| Other event renames | Keep their numeric values, including Pink Bow → FairyFeather, Katy → Larry, Wilhomena, and renamed map events. Deleted flags were reserved with `const_skip`, so later flags do not shift. |
| Trainer House opponent Euna inserted | Shift saved daily opponents 4/5 (En/Madoka) to 5/6; keep 0 and 1–3. |
| Reserved bytes become weather/palette fields | Initialize the new fields and force weather regeneration. See the separate options audit for nickname and text-pause bits. |
| Saved object caches contain old pointers and movement state | Clear NPC structs/map objects/masks until the player exits, reset the player's step state and repurposed flags, clear follower state and the cached scene pointer, and use the normal upstairs scene. Translate cached `SPRITE_MON_ICON` from `0xef` to `0xee`. |
| Battle facility ROM tables changed | Translate rental/team-history set indexes as detailed above; preserve trainer history, normal-mode selections, streaks, rewards, and stored player Pokemon. |

Arbok conversion covers all six party slots, both Day Care parents, the reserved leveling slot, the contest backup, hidden-grotto Pokemon, roamers, all six box-database regions, and all ten Hall of Fame teams. Box data uses species/form bytes, not the flattened dex index. Only valid checksummed database records are converted, and their per-mon checksums are rewritten without changing encoded names. Invalid records remain invalid; the patch does not turn Bad Eggs into apparently valid Pokemon.

The game reloads map header/warp/background pointers during Continue, but retains saved object structures. NPCs are temporarily absent upstairs to prevent following obsolete script pointers. Exit downstairs immediately; map entry reloads objects normally. Save near the stairs before conversion, as with earlier patch versions.

## Reviewed changes that do not require conversion

- Pokemon/breed/party/save-mon/Hall of Fame structures and box metadata retain their layouts. There is no new global species-ID remap.
- Item IDs retain their values; FairyFeather replaces Pink Bow at `0x8a`. Move IDs and caught-location landmark indexes remain stable. The Underground landmark is renamed at index `0x53`.
- Save-visible names and mail use stable uncompressed character codes. ROM Huffman/n-gram changes do not require re-decoding version 10 player text.
- Ability/type/stat changes are game balance changes. Pokemon store an ability slot, not a global ability ID; the selected slot is preserved, so its resulting ability can change (for example, regular Raichu's hidden slot becomes No Guard). The game recalculates party stats on Continue and storage stats on retrieval. Facility sets are loaded from the new ROM: their Lightning Rod Raichu changes slot to keep Lightning Rod, and Dudunsparce's hidden ability becomes Sand Stream in the non-faithful build.
- Radio channel enums are runtime state. The saved tuning knob stores its position, not the renumbered channel enum.
- Engine-flag constants are lookup-table selectors, not positions in one saved bitfield. Only the visited-spawn bitfield needs the Fly-point insertion.
- Scene-script constants replace existing numeric scene values; the renamed scene variables retain their offsets. Story scene progress is retained.
- Most WRAM0/HRAM and graphics/audio changes are outside saved blocks. Map tilesets, environment enums, and ROM text/script addresses are reloaded; arbitrary outdoor saves are deliberately not supported.

## Validation

Run `make test` for the 12 existing byte-for-byte golden-file regressions and 12 version 11 test groups. The new tests cover both real-save migration chains from versions 7–10, bitfield insertion boundaries, every changed map pair, all stored Arbok formats and box-bank boundaries, invalid box checksums, legendary roamer initialization, event/weather defaults, removed Snowtop stairs, unrelated-data preservation, RTC trailers, both save checksums, bad checksums, interrupted saves, wrong locations, and repeated migration/downgrade rejection. Option tests exercise all 256 byte values in both saved copies, verifying initial choices are preserved. Facility tests exercise all 432 valid set IDs in each party/history field, plus sentinels, invalid values, normal-mode aliases, and progression preservation.

The version 11 fixtures are generated during tests and are **not** labelled human-verified golden files. Emulator smoke testing uses the built destination ROM and vibeEmu; those observations are separate from the byte-level tests.

Both MrKat and ProtoBlues saves were converted, booted in vibeEmu against the destination ROM, and walked downstairs to Violet and Cherrygrove respectively. MrKat also exited to Violet City, saved through the game's menu, rebooted using the new SRAM, and moved successfully after Continue. The ROM accepted the version and checksums before and after the in-game save.

After the follow-up corrections, a controlled MrKat copy with non-default initial choices, `RESET_INIT_OPTS` clear, Instant text, Mono sound, Serif typeface, frame 8, QWERTY, and dirty nickname/text-pause/roamer bits was converted and loaded in vibeEmu. The initial choices remained unchanged without an initial-options prompt. The in-game menu displayed the retained settings and **Nicknames: Ask**. After an in-game save, cold boot, Continue, and movement, all tested settings and the three initialized roamer forms remained intact.

The release WebAssembly build succeeded with Emscripten 3.1.63. Its `patch_save_js` binding produced byte-identical output to the CLI for both version 10 fixtures, reported output version 11, and rejected a second migration. The browser's target-selection functions defaulted versions 7–10 to 11 and disabled migration for an already-version-11 save.

## Review depth and limits

This is an endpoint source/layout audit across the 884-commit range, with semantic tracing of saved fields and Continue/save/storage consumers, generated map translation, assembled-ROM comparisons, targeted regression tests, and emulator smoke tests. It is not a line-by-line review of every commit or a complete gameplay playthrough. Labeled-PR discovery and maintainer comments are an additional checklist, not a substitute for source comparison. The first pass lacked that checklist and the explicit option coverage; the corrections above are the result of adding them.

Both vendored player fixtures originate from older migrations, so they cannot represent every v3.2.3 gameplay state. Synthetic boundary cases cover the newly identified conversions, but a full Factory challenge, every initial-option combination in gameplay, every story branch, and faithful-ROM gameplay have not been emulator-tested. Intermediate unreleased version 10 saves remain outside the supported input contract.
